## Schema-convention note for whoever merges this

I matched the flat 8-key `image_proposal` shape exactly as instructed. Before writing, I read a sample of S5A's own already-completed records directly (`s5a_batch1_2026-08-26.jsonl` through `s5a_batch10...jsonl` in the `s5a-summer-academic-enrichment` worktree, read-only, not edited) to see their real conventions, and found three small differences from the schema template I was given:

1. **`image_url` format:** S5A's own cleared records always use the fully-resolved `https://upload.wikimedia.org/wikipedia/commons/<hash>/<hash2>/<Filename>` form. My task brief explicitly specified the `Special:FilePath` redirect form instead, which I used throughout (every one of the 7 URLs in the output file was navigated to directly and confirmed to redirect correctly to the right image at the right dimensions). Both forms are functionally identical (Special:FilePath is a stable, documented Wikimedia redirect), but whoever merges may want to resolve them to S5A's usual form for internal consistency.
2. **`image_depicts` format:** S5A's own records use a short fixed category (`"host_campus"` or `"venue"`) rather than descriptive text. My task brief's own schema and worked examples clearly called for descriptive text (including caveats like "a component exists and wasn't found"), which I followed, since several of these 7 records have nuance (rotating hosts, reused cross-record photos, alternates) that a two-value enum can't carry. Recommend whoever merges adds a short `host_campus`/`venue` tag alongside my longer text rather than replacing it outright, since a couple of records (NSLC's DC-visit alternates, Ross's 2012 program photo) are genuinely neither.
3. **`rights_status` format:** S5A's own records use a short cleared-status keyword (`cleared_cc_by_sa`, `cleared_public_domain`, etc.), while my task brief's schema explicitly said this field "should become the actual license string if verified" -- which is what I did. Easy to map: every `rights_status` value in the output file here is a license string that corresponds 1:1 to one of S5A's existing `cleared_*` keywords.

None of this affects correctness of the sourcing itself -- it's purely about which literal strings land in which field on merge, flagged so nothing gets lost in translation.
