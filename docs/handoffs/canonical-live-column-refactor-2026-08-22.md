## 3. New API shape

`lib/universities/canonical.ts`'s five sync helpers (`isSupersededUniversityId`,
`canonicalUniversityId`, `getSupersededUniversityIds`, `excludeSupersededUniversities`, plus the
now-removed `allSupersessions`) used to close over a module-level constant loaded from the JSON
file at build time. They're now pure functions that take a `SupersessionMap` (`loserId ->
{winnerId}`) as their first argument, loaded fresh via one of two async functions:

- `loadSupersessionMap(supabase: SupabaseClient<Database>)` — every app/lib call site and most
  scripts, which already hold a supabase-js client.
- `loadSupersessionMapViaRest(target: PostgrestTarget)` — the acquisition scripts, which read
  everything via the raw-REST `fetchAllRowsVerified` convention (`lib/acquisition/paginate.ts`)
  rather than constructing a supabase-js client for reads.

Pattern used at every call site: load the map once per request/script/function, pass it to the
already-synchronous helpers exactly like before. Where an exported entry point fans out into
same-file private helpers via `Promise.all` (`buildStudentAdvisorContext`, `scanDeadlines`,
`getUpcomingDeadlines`), it loads the map once and threads it down as a parameter rather than
each helper loading its own copy — avoids redundant round trips to what is still just a 9-row
indexed-column query. Every other call site loads it inline since it's the map's only consumer
in that function. No attempt was made to build a single request-wide cache (e.g. `React.cache`)
— it would only cover Server Component call sites, not the Server Actions/cron jobs/scripts that
also need this, and the query is cheap enough (9 rows, `duplicate_status` is indexed) that a
handful of redundant loads per page is not worth the added indirection.

`pickCanonicalWinner`/`DuplicateCandidate` are **unchanged** — out of scope per the assignment
("identity/merge-adjacent decision logic, not a read helper"). `scripts/resolve-university-
duplicates.ts` (their only production caller, whose entire job was generating the now-deleted
JSON file) is deleted, so they currently have zero production callers, only their own test file
(`__tests__/universities/canonical.test.ts`). Kept rather than deleted: the assignment flagged
deletion as conditional on the logic being "genuinely dead," and there's a real future use for
it — `docs/MASTER-EXECUTION-STRATEGY.md` §P1 explicitly plans to extend canonical-identity
work to schools, employers, and other entity types, and this is the only tested implementation
of "score competing duplicate candidates by FK richness / website_url / name cleanliness /
creation order" in the codebase. This is a judgment call, not a certainty — flagging it
explicitly for the founder/coordinator rather than deciding unilaterally that it's dead.

## 4. The one script with no live DB connection

`scripts/stage-programs-ingestion-dryrun.ts` is a point-in-time analysis tool for a specific
2026-08-21 batch — it has no `NEXT_PUBLIC_SUPABASE_URL`/`SUPABASE_SECRET_KEY` available and reads
four static JSON snapshots from `.night-scratch/` (fetched once, externally, via the Supabase MCP
tool) instead. Neither `loadSupersessionMap` nor `loadSupersessionMapViaRest` is callable here —
no client, no url/key. Fixed by extending the script's own `UniRow` snapshot type with
`duplicate_status`/`superseded_by_id` and building the `SupersessionMap` locally from the
already-loaded `universitiesRaw` snapshot, reusing the same `SupersessionEntry`/`SupersessionMap`
types and the same `canonicalUniversityId`/`excludeSupersededUniversities` pure functions — just
skipping the network round trip since the snapshot already has the data once its own type
carries the two columns. Documented in the script's own header: a future snapshot must include
these two columns or every university will silently resolve as "canonical" (no error, just
under-filtering). Note: `.night-scratch/` does not currently exist in this repo (confirmed before
editing) — this script cannot run today regardless of my change, a pre-existing condition from
whenever that scratch directory was cleaned up, unrelated to this package.

## 5. Two real bugs found by typecheck, not anticipated in the brief

**`types/database.ts` never got `duplicate_status`/`superseded_by_id` added.** This hand-authored
file (see `reference_check_provenance_before_regenerating_files` — it looks generated but isn't)
was apparently not updated when migration 0043 shipped and was backfilled on 2026-08-20. Once
`loadSupersessionMap` tried to `.select("id, superseded_by_id").eq("duplicate_status", ...)`
against the typed `Database`, `tsc` correctly rejected both the column name and the select shape.
Added both fields to the `University` interface (`duplicate_status: "canonical" | "superseded"`,
matching the migration's CHECK constraint; `superseded_by_id: string | null`) and to
`UniversityInsert`'s omit-list (both are DB-defaulted/nullable, never required at insert time).
Also updated `lib/dev/fixtures.ts`'s two `University` stub objects (`stubUniversity()` and
`FIXTURE_UNIVERSITY`) with the two new required fields — trivially `"canonical"`/`null` since
they're synthetic dev fixtures, not real duplicate pairs.

**`lib/search/index.ts`'s `searchApplications()` had a second, missed call site.** The first
lib/ pass caught `searchPrograms()` in the same file (which also calls `canonicalUniversityId`)
but missed `searchApplications()` — both are private helpers in the same file, easy to miss on a
manual read-through. Typecheck caught the stale single-argument call immediately once
`canonical.ts`'s signature changed; fixed the same way as every other call site (load the map,
pass it through).

Neither of these was mentioned in the assignment brief — surfacing them explicitly since they're
exactly the kind of thing "get the current authoritative list yourself" was meant to catch, and
both would have been silent, undetected gaps (the first a straight-up type error blocking any
build; the second a working-but-wrong call that `tsc` happened to catch only because the
function signature changed under it, not because anyone was looking for it).

## 6. Test changes and the −2 test-count delta

`npm run test` before this package: 121 files / 1826 tests (the UI-QUALITY-PASS baseline
recorded in `docs/ORYN_WORKSTREAMS.md`). After: **121 files / 1824 tests** — a deliberate,
fully-accounted-for delta of exactly 2, not a silent loss:

1. `__tests__/universities/duplicate-regression.test.ts`'s "exactly these 9 pairs are recorded"
   test asserted the JSON snapshot's own key set against a hardcoded `KNOWN_PAIRS` list — its
   entire premise (a committed static snapshot to diff against) no longer exists once the module
   queries the DB live. Removed, with a comment explaining that live-state correctness is now a
   DB-level property (enforced by `duplicate_status`'s `NOT NULL`/CHECK constraint, and
   maintained by `scripts/university-duplicates-audit.ts --supersede`), not a unit-testable one
   in an environment with no DB connection available to tests.
2. `__tests__/entities/search.test.ts`'s "fixture sanity: the real duplicate-supersessions data
   still has a UCL entry" test asserted that `allSupersessions()` (now deleted) contained a UCL
   row — replaced the whole fixture with a hardcoded UCL pair (same style as
   `duplicate-regression.test.ts`'s own `KNOWN_PAIRS`), so the sanity check is now tautological
   (a constant equals itself) and was dropped along with it.

Every other test in both files, plus `__tests__/universities/canonical.test.ts` and
`__tests__/programs/ingest.test.ts`, was adapted to the new map-parameter signature and kept.
`__tests__/entities/search.test.ts`'s mock Supabase client gained an `.eq()` method and every
fixture `UniversityRow` gained `duplicate_status`/`superseded_by_id` (defaulted to
`"canonical"`/`null` via a `withDuplicateDefaults()` helper so existing fixtures didn't need
individual edits) — `searchUniversities()` now issues a second, independent
`.from("universities")` query (inside `loadSupersessionMap`) against the same mocked table
alongside its pre-existing one, and the mock needed to support both query shapes against shared
in-memory row state, the same way real Postgres would.
