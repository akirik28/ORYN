## What this closes

Two confirmed findings from the audit, both real gaps in the exact path a first-time,
Turkish-speaking student hits before they've entered anything:

1. `lib/scoring/completeness.ts`'s profile-completion checklist labels ("Add an activity",
   "Set a career goal", 13 more) were hardcoded English literals with no Turkish
   counterpart at all — not caught by any of the three i18n guard tests, since they're
   neither raw-map-indexing (`label-accessors.test.ts`'s target) nor a missing catalog key
   (`translation-keys.test.ts`'s target), just plain unlocalized strings. These titles are
   what a brand-new, near-empty profile's Dashboard "This week" panel and Advisor "Your
   priorities" panel actually show — scored `impact: high` when completeness is under 50%,
   so they're likely to be the literal first substantive content a new student sees.

2. `features/profile/field-config.ts` — 400 lines, ~137 unique user-facing strings (field
   labels, placeholders, select options) across 14 exported `FieldConfig[]` arrays, zero
   locale references. Every achievement form a student fills in (`achievement-section.tsx`'s
   full Edit dialog and `quick-add-entry.tsx`'s short form, both rendering through the
   shared `DynamicFormFields` component) was English-only. `check:i18n`'s scanner had never
   seen it — it only walked `.tsx` files; oryn-a7 fixed that gap separately (`a25d18ce`) and
   it's what surfaced this file in the first place.

Also finished, per oryn-a7's explicit "take #2/#3 as well":

3. 7 of the 14 achievement-section empty states on `/profile` were the spec's own literal
   "Bad:" example ("No {noun} yet." with zero elaboration) — education, testScores,
   projects, workExperience, volunteering, awards, certifications. Now match the other 7's
   "Better:" pattern (what to add, sometimes why), in both locales.

4. Portfolio's empty state (`features/profile/portfolio-view.tsx`) had no CTA button and
   weaker copy than its siblings. Added a "Go to Journey" button linking to `/profile` and
   rewrote the copy to say what to add and where.

## The stable-key fix (the part oryn-a7 flagged as "will bite")

`lib/counselor/candidates.ts`'s `profileTaskCandidates()` used `item.label` — the raw
English display string — as `source.checklistKey`, which `lib/counselor/evidence.ts`'s
`sourceId`/`recommendationId` slugifies into that recommendation's `id`. Translating the
label in place would have silently repointed every recommendation's identity the moment a
Turkish student loaded the page.

Fixed by splitting identity from display text, same shape as every other locale-aware
accessor added this session (`dimensionLabel`, `eligibilityMessages`):

- `CompletenessChecklistItem` gained a `key: CompletenessChecklistKey` field (a 15-value
  string literal union — `school_details`, `activity`, `career_goal`, ... — one per
  checklist item). `label` stays as the English text, unchanged, for the one caller that
  already read it directly.
- New `completenessChecklistLabel(key, locale)` resolves either language from the key.
  `CHECKLIST_LABELS_EN` is now the single source for the English text too (the checklist
  builders reference it rather than duplicating the literal inline).
- `candidates.ts`'s `profileTaskCandidates(state, locale)` now sets
  `checklistKey: item.key` (stable) and `title: completenessChecklistLabel(item.key,
  locale)` (translated) — threaded `locale` through where it wasn't before.
- The same split needed applying at `app/(app)/profile/page.tsx`'s "Profile Strength"
  suggestions list, a *third* consumer of the checklist beyond the two Counselor Core
  panels — it rendered `item.label` directly too.

## `field-config.ts`'s translation approach

Not a next-intl catalog namespace — `FieldConfig[]` is structured config data (many fields,
each with label/placeholder/select-options), and mirroring that shape into JSON would have
meant ~137 deeply-nested catalog keys with no real benefit over the existing pattern. Went
with a resolver function instead, matching this session's established accessor shape:

- `FIELD_TEXT_TR: Record<string, string>` keyed by the **exact English source string**, not
  by field `name`. `name` is already a stable identifier (the DB column, e.g.
  `"start_date"`) but the same `name` means different things in different arrays
  (`SPORTS_FIELDS`'s `level` is Recreational..International; `COURSE_FIELDS`'s `level` is
  Regular..Dual enrollment) — keying by source text instead means `STORY_NOTES_FIELD`
  (shared by 5 arrays) only needs translating once, and any two fields with identical
  English text get identical Turkish text regardless of which array they're in.
- `localizeFields(fields, locale)` returns a translated copy — `name`, `type`, `quickAdd`,
  `span`, `scope`, `entityIdField`, `allowCustom`, and `suggestions` (a separate, larger
  surface in `lib/vocabularies/*`) are untouched.
- Called once, inside `DynamicFormFields` (the single shared rendering component both
  `achievement-section.tsx` and `quick-add-entry.tsx` render through) — neither caller
  needed a single line changed.
- `customLabel` deliberately NOT translated — `features/entities/entity-combobox.tsx`'s own
  header comment already explains why (free text belonging to that file's territory; the
  Turkish "cantFind"/"addTitle" catalog keys are built not to need it).
- Deliberate loanword exceptions, matching existing convention: AP/IB/A-Level/Honors
  (curriculum terms), Mentor (matches `messages/tr.json`'s own
  `profile.recommendations.relationships.mentor`), Poster (identical spelling/meaning in
  both languages).
- Explicitly **not** translated: `LANGUAGE_FIELDS`'s `proficiency` options, which come from
  `lib/vocabularies/languages.ts`'s `LANGUAGE_PROFICIENCY_OPTIONS` (Native, Bilingual, C2 —
  Mastery, ...) — a real, separate 16-string gap (labels + hints) oryn-a7 flagged as a
  different file, not part of this assignment.

## Tests

New: `__tests__/profile/field-config.test.ts` (7 tests) — English is a no-op; Turkish
translates label/placeholder/option-labels; the same English string translates identically
across different arrays while the same field `name` can mean different things in different
arrays; curriculum loanwords fall through on purpose; `name`/`type`/`quickAdd`/`customLabel`
stay untouched; and one exhaustive test that walks every exported `*_FIELDS` array and
asserts every label/option-label actually changed under Turkish, with a named,
commented exception list rather than a blanket skip.

Extended `__tests__/scoring/completeness.test.ts` — every checklist item has a key, all keys
unique; `completenessChecklistLabel`'s English matches each item's own `label`; Turkish is
real and distinct for every key, not a silent fallback.

Fixed `__tests__/counselor/candidates.test.ts`, `contract.test.ts`,
`dashboard-contract.test.ts` — all three hand-construct `CompletenessChecklistItem` fixtures
and needed a `key` added now that it's required. `candidates.test.ts`'s
`"opportunity and profile-task titles are untouched by locale"` test asserted the old (now
wrong) behavior — split into two: opportunity titles genuinely stay untouched (the
opportunity's own stored text), and a new test that profile-task titles now translate while
`source.checklistKey` provably does not move (regression coverage for the exact bug this
fix prevents).
