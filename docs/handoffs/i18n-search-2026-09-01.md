# Search i18n — the `search` namespace, and the last English-only label map

Branch `oryn/i18n-search-2026-09-01`, based on `cf257fb1`. The founder's own live report —
*"türkçe seçeneğinde neredeyse sadece başlıklar türkçe, gerisi ingilizce kalmış"* — split
across four lanes by CEO. This package: `features/search` (`command-palette.tsx`,
`search-view.tsx`) plus `lib/search/types.ts`'s `SEARCH_RESULT_TYPE_LABELS`, named as the
last English-only label map with a student-facing consumer and no locale-aware accessor
(`docs/i18n-coverage.md`).

## What changed

**`lib/search/types.ts`** — new `searchResultTypeLabel(type, locale)`, same shape as
`lib/scoring/labels.ts`'s `dimensionLabel`: `SEARCH_RESULT_TYPE_LABELS` stays English-only
and untouched, a new private `SEARCH_RESULT_TYPE_LABELS_TR` sits beside it, the function
picks one by locale. Both call sites (`command-palette.tsx`'s group headers,
`search-view.tsx`'s result-type chips) now call the accessor instead of indexing the map.

**`messages/en.json` / `messages/tr.json`** — new top-level `search` namespace, two
sub-namespaces matching the two components: `search.view` (7 keys) and
`search.commandPalette` (9 keys), 16 total. Both catalogs hold the identical key set —
checked programmatically, not eyeballed, before writing any component code.

**`features/search/search-view.tsx`** — was a synchronous component reading a hardcoded
English string literal at every call site. Now `async`, calls `resolveLocale()` +
`getTranslations("search.view")` (the same pairing `app/(app)/universities/[id]/page.tsx`
already established for a server component that needs both a translator and a locale value
for an accessor call). No caller change needed — `app/(app)/search/page.tsx` already renders
it as `<SearchView ... />`, and an async Server Component is awaited by the framework
automatically.

**`features/search/command-palette.tsx`** — client component, `useTranslations` +
`useLocale()` (the pairing `features/opportunities/opportunity-card.tsx` already
established for the identical shape: a translator for static strings, a locale for calling
an accessor function inline). Every string in both the "icon" and "bar" trigger variants
now goes through `t()`. `Esc` and `⌘K` are deliberately left as literal key names, not
translated — matching this codebase's existing convention that a real product/interface term
without a natural translation stays verbatim (the same reasoning `lib/requirements/copy.ts`
already documents for ETS/IELTS product names).

**`__tests__/i18n/label-accessors.test.ts`** — added `SEARCH_RESULT_TYPE_LABELS` to
`MAPS_WITH_ACCESSORS` and `searchResultTypeLabel` to the `LOCALE_AWARE` detection regex.
It wasn't in the guard's list before this branch — CEO named it as the map to close, and
closing it without also protecting it here would leave the exact gap this whole i18n push
exists to catch invisible to the one test built to catch it.

## Verified live, both locales, real measurements — not the diff

Started this worktree's own dev server directly (`next dev -p 3611`, backgrounded via Bash)
rather than through `preview_start`, which collides with another chat's already-running
server on this machine — a known quirk from earlier tonight. Switched locale through the
real UI control (Settings → Language), not a hand-set cookie — a direct
`document.cookie` write didn't stick on this account (didn't chase why; the real toggle is
the actual student-facing mechanism anyway and is what needed testing).

- **Turkish**: `/search?q=eco` shows heading "Arama", placeholder
  "Üniversitelerde, fırsatlarda, profilinde ara…", "Aramayı temizle" clear link, and every
  result correctly labeled by type — "Program", "Fırsat", "Üniversite" — read from the live
  accessibility tree, not assumed from the source.
- **English**: same page, same query, after switching back — "Search", "Clear search",
  "Opportunity", "University" (5 more results below).
- **The command palette's "bar" trigger** (`⌘K` top bar, Turkish's longer string is the
  real clipping risk `docs/i18n-coverage.md` flags): measured, not eyeballed —
  `scrollWidth: 199, clientWidth: 199, clipped: false` on the live element holding
  "Üniversite, program, yarışma ara…". The pre-existing `truncate` class (added by this
  component's original author for exactly this reason, per its own code comment) holds.
- **The uppercase-styled group header** — the one element in this package actually at risk
  of the dotted-İ bug documented in `docs/i18n-coverage.md` (`text-transform: uppercase`
  under `lang="tr"`). Ran the coverage doc's own probe against the live, rendered elements
  after opening the command palette and searching "eco": `"Üniversite"` → `"ÜNİVERSİTE"`,
  `"Fırsat"` → `"FIRSAT"`. Both correct — including `Fırsat`, which exercises the *other*
  Turkish casing pair (`ı`→`I`, dotless) the single dotted-İ example doesn't cover on its
  own. Confirms this element is safe because the text is now genuinely Turkish, not because
  the element avoids `lang`.
- Reset the account's language preference back to English before finishing, via the same
  real UI control — this is the founder's own persisted browser session, not a disposable
  test account, so it was left as found.
