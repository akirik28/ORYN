## One thing worth carrying forward as a working pattern, not just a finding

P8's actual product insight, per CEO's framing: **when two facts genuinely need to
coexist, the fix is two rows, not one field fighting over both values.**
`university_deadlines.verification_state` already does this correctly (one row per dated
event, so "last cycle closed" and "next cycle not yet published" can be two separate rows
instead of one contested enum) — a working precedent already shipped in this codebase,
not a new design proposal. Worth reaching for before inventing a new enum value the next
time a "one field, several simultaneous truths" problem shows up anywhere in the app.
