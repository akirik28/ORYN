# ORYN Workstreams — live ownership map

**Purpose:** prevent duplicate work across concurrent Claude agents. This file answers
*who owns what, on which branch, right now* — nothing else. It is rewritten in place per
workstream row, not appended to as a log.

**This is not a duplicate planning system.** The other three canonical documents already
exist under different names and are not reproduced here:

- **Master plan / product direction** → [`docs/MASTER-EXECUTION-STRATEGY.md`](./MASTER-EXECUTION-STRATEGY.md)
- **Operational status / live coverage numbers** → [`docs/current-state.md`](./current-state.md)
  (rewritten at each integration checkpoint, not appended to — check its own "last
  measured" date before trusting it; a stale copy is worse than no copy)
- **Permanent decision log** → [`docs/product-decisions.md`](./product-decisions.md)

If you're about to create `ORYN_MASTER_PLAN.md`, `ORYN_STATUS.md`, or `ORYN_DECISIONS.md`,
stop — those roles are already filled by the files above.

## How to use this file

Before starting a substantial new package: `git fetch --all --prune`, re-read this file,
confirm nobody already owns what you're about to do. Claim your row (update it) before
starting large work; update it again when you finish or hand off. Do not rewrite another
agent's row from assumption — verify from git log/live DB first, then correct with
evidence if it's actually wrong.

## Standing operating rules

Adopted 2026-08-21 after real failures this session, not written speculatively:

1. **One worktree per lane. Never work in the shared main checkout.** Three sessions had to escape it overnight; two lost work to concurrent overwrites of the same file paths.
2. **Claim your row here before starting substantial work.** Update it when you finish or hand off.
3. **Commit and push every coherent checkpoint.** Uncommitted work is invisible to every other lane and to Integration.
4. **Namespaced `RULE-*` IDs.** Any lane minting rule identifiers takes an assigned range and states which; never start at 001. Two lanes independently minted `RULE-COUNSEL-001`–`033` overnight and produced 33 colliding IDs for 33 genuinely different rules — see COUNSELING-REGISTRY-UNIFICATION.
5. **Research is not production.** `RESEARCHED → EVIDENCE-CHECKED → QA/DEDUP → INTEGRATION-READY → PRODUCTION-APPROVED`. A researched record is not approved data.
6. **Re-fetch live database state immediately before any write.** The live database is a second, non-git collision surface with no branch signal.
7. **The gate runs against the final tree after a merge wave, not only per-branch.** Adopted after seven individually-green branches produced a red `main` — the Integration Manager caught this by re-running fresh rather than trusting a reported result.
8. **Never resolve a content conflict by silently picking a side.** Preserve both and escalate — see `docs/research/counseling-intelligence/CONFLICT-NOTICE-00-and-02.md` for the worked example.
9. **Ask what a session is already doing before assigning, and treat "already assigned by the founder" as occupancy.** A new assignment that conflicts with an existing one is a reconciliation event — the receiving lane should flag it and keep working, not switch silently and not stop.
10. **One ownership-map file, one owner.** This file (`docs/ORYN_WORKSTREAMS.md`) is canonical. A second ownership document (`docs/ORYN-LANE-REGISTRY.md`) was created 2026-08-21 in violation of this file's own opening warning against exactly that; it has been reduced to a pointer stub rather than deleted outright, so a stale link doesn't recreate the duplication. The Integration Manager owns this file going forward — route ownership-map changes through it rather than editing directly.

## Open founder escalations — not agent decisions to make unilaterally

1. **`ANTHROPIC_API_KEY` is empty**, requires paid credit — every AI-backed surface is dead (see release-readiness pass for the exact per-route breakdown). **`TAVILY_API_KEY`** also empty (a free tier exists) — opportunity/requirement discovery via Tavily is dead without it.
2. **Source-authority gate is too narrow.** `lib/acquisition/source-authority.ts`'s `looksOfficial()` accepts only `.edu`/`.ac.`/`.gov` domains; the `opportunities` fact class is official-domain-or-nothing. This rejects UCAS, CAO, Studielink, Hochschulstart, and Common App — application systems this project's own briefs name as valid deadline authorities — and nearly every Turkish/European youth organisation (`.org.tr`, `.com.tr`). Proposed fix: an organiser-domain provenance field feeding `sourceAuthority()`'s existing `officialDomains` parameter. This is a provenance-modeling problem, not a reason to lower the evidence bar.
3. **Scalar columns that cannot hold real values.** `opportunities.cost` is `numeric` but real records carry multi-tier/multi-currency pricing; `university_programs.duration_years` is numeric against durations like "3 years (4 with placement)". Decide: widen to text, add a structured companion field, or accept lossy extraction only where unambiguous.
4. **Unweighted 9-dimension average** in `lib/scoring/index.ts` — confirmed by live persona runs (see COUNSELOR-LOOP-QA): a strong founder/leadership-shaped profile scores 21/100 overall because untouched dimensions drag a flat mean down. Design question, deliberately not changed unilaterally by any lane.
5. **Drive-vs-chat product conflicts** — messaging scope and light/dark theme. See `docs/known-issues.md` §1; a requirements-audit lane is establishing what the app actually does today.
